# VLA Scheduling-Block Grader

An automated grader for **VLA Scheduling Blocks (SBs)** in the OPT text-import format (`VERSION 7`). It checks an SB — typically one generated by an LLM from a natural-language request — against NRAO/VLA rules, and can also verify it against a known-good ("ground-truth") SB. The goal is to catch mistakes (wrong hardware name, wrong scan order, too little on-source time, a mis-pointed target, …) before any telescope time is used.

Scoring convention: **1/1 per rule satisfied, 0/1 per rule violated** — nothing scores negative, and the maximum is one point per rule. A rule that cannot be decided automatically raises a **HUMAN REVIEW FLAG**: it takes the else branch (0) provisionally and a human then rules it 1 or 0, so in the final score every rule is either 1/1 or 0/1 (see [Human review](#human-review)). Per-rule point values are configurable — see [Changing the scoring](#changing-the-scoring).

## What it checks

Every check reports where its verdict came from:

| Source tag | Meaning |
|------------|---------|
| `AUTO`     | deterministic code check (format/validity) |
| `CALC`     | computed vs NRAO guidance (cycle time) |
| `CATALOG`  | resolved from `targets.csv` (target pointing) |
| `REQUEST`  | compared against the requested time in `requests.csv` |
| `GROUND`   | verified against the ground-truth SB |
| `LLM`      | model estimate (fallback only) |
| `HUMAN`    | ruled 1 or 0 by a human reviewer |
| `MANUAL`   | left unresolved — needs a human |

Three "expert-judgment" checks (phase-cal validity, phase-cal separation, pointing) resolve in priority order: **ground truth → catalog → LLM → human review flag.** So when a ground-truth SB is available, most of them become automatic and deterministic, and the LLM is only a fallback. See [`docs/HANDOFF.md`](docs/HANDOFF.md) for the full rule list and design notes.

### Observing time

The fourth external check, `total_time_matches_request`, compares the **total SB duration** with the time the observer asked the LLM for (`requests.csv`, or a duration token in the filename such as `_3h25m_`, or `--requested 2hr`). It needs no ground truth and no LLM.

The check is **one-sided**: an SB that overruns its allocation fails, because it cannot run as scheduled; one that comes in under passes, because it is still executable and merely leaves time unused. `TOTAL_TIME_TOL_SEC` (top of `score_sb.py`, default `0`) adds slack on the overrun side only.

By default the duration scored is the sum of the declared `DUR` fields. **That is a lower bound** — it omits the slew and settle time the OPT adds at every source change, and the gap grows with the number of scans, so it understates most for the many-short-scan SBs the LLM tends to produce (~3 min on the SN2025ulz Ku SB). If you want the number the telescope actually acts on, import the SB, read the total off the OPT, and put it in the `opt_total` column of `requests.csv`; it is then scored in place of the `DUR` sum.

It deliberately does *not* score on-source time. The split of a fixed allocation between overheads and target scans is an observing-strategy choice — two experienced observers may divide the same block differently and both be right — and the sensitivity actually delivered can only be established once the SB is in the OPT with the Exposure Calculator. On-source time is still measured and printed against the ground-truth SB, but as an informational line worth zero points.

The requested time must come from outside the SB. The generated SB's `SCHED-BLOCK` comment contains the model's own "total duration approximately …" self-report; checking against that would be circular and would pass unconditionally.

## Human review

Every rule ends up worth 1 or 0. When neither the code, the ground-truth SB nor the LLM can decide one, it is **not** scored as a third outcome: the report raises a `HUMAN REVIEW FLAG`, the check takes the else branch (0) for now, the score line is labelled `SCORE (provisional)`, and the unresolved rules are listed at the bottom of the report.

Rule on them interactively with `--review`:

```bash
python src/llm_judge.py examples/*_AItest.txt --ground-auto --no-llm --review
```

For each flagged check you get its title and the automatic verdict, and answer `1` (met) or `0` (not met). Anything typed after the digit is kept as a note and shown in the report:

```
  [1/2] phase_cal_visible
        Phase calibrator observable in chosen band and array config
        automatic verdict: FLAG -- needs expert judgement / manual review
        score 1 or 0 (+ optional note): 1 real VLA cal, P code, point-like at Ku
```

Pressing Enter alone leaves a check unresolved, so it stays flagged and keeps scoring 0. Once nothing is pending the report is reprinted with the final score and the ruled checks carry the `HUMAN` source tag.

Add `--review-file FILE` to record the rulings as `sb_name,check_id,score,note` CSV. The file is read *before* scoring and appended to as you answer, so a later run replays the same rulings and prints the same final score without asking again — which is what makes a graded run reproducible:

```bash
# first pass: rule on the flagged checks and record them
python src/llm_judge.py examples/*_AItest.txt --ground-auto --review --review-file reviews.csv

# later: same score, no questions asked
python src/llm_judge.py examples/*_AItest.txt --ground-auto --review-file reviews.csv
```

Both `score_sb.py` and `llm_judge.py` accept `--review` and `--review-file`.

## Requirements

- **Python 3.8+** — the offline modes use only the standard library (no `pip install`).
- **`openai`** — only for the LLM fallback (`pip install -r requirements.txt`), plus access to the lab's Argo gateway. Everything else runs without it.

## Quick start

Grade the example SBs, verifying the expert checks against their ground truth, with **no LLM** (fully deterministic, no Argo, no API key):

```bash
python src/llm_judge.py examples/*_AItest.txt --ground-auto --no-llm
```

Full run, using the Argo LLM only where ground truth can't decide:

```bash
python src/llm_judge.py examples/*_AItest.txt --ground-auto --model "Claude Opus 4.8"
```

A sample of this full run is saved in [`report.txt`](report.txt), produced with:

```bash
python src/llm_judge.py examples/*_AItest.txt --ground-auto --model "Claude Opus 4.8" > report.txt
```

Just the rule-based grader (no ground truth, no LLM):

```bash
python src/score_sb.py examples/*_AItest.txt
```

Compare an AI SB against its ground truth (structural diff, no scoring):

```bash
python src/compare_sb.py --auto --dir examples
```

### Useful options (`llm_judge.py`)

- `--ground-auto` — auto-pair each file with its `*_ground.optSB` and use it as the oracle.
- `--ground <file>` — set the ground-truth SB explicitly (single-file mode).
- `--no-llm` — skip the LLM entirely; unresolved external checks show as `MANUAL`.
- `--targets <csv>` — target-position catalog (default: `targets.csv`).
- `--requests <csv>` — requested-time catalog (default: `requests.csv`).
- `--requested <dur>` — requested total duration for the SB(s) on the command line, e.g. `2hr` or `3h25m`; overrides the catalog and the filename.
- `--model <name>` — Argo model, e.g. `GPT-5.5` or `Claude Opus 4.8`.
- `--user <ANL-username>` — Argo API key is your ANL username (or set `ARGO_USER`).
- `--review` — interactively rule 1/0 on every check that raised a human-review flag.
- `--review-file <csv>` — read/record human rulings so reruns reproduce the score.

## Changing the scoring

Every rule lives in [`rubric.yaml`](rubric.yaml), one entry per check, and the score it contributes is set by two optional fields — no Python changes needed.

- `points` — awarded when the rule **is met** (PASS). Default `1`.
- `fail_points` — awarded when the rule **is not met** (FAIL). The shipped rubric sets `fail_default: 0` in its `meta` block, so an unmet rule scores `0` rather than costing a point.

Anything still unresolved awards `0` **provisionally** and is raised for human review; once a human rules it, it scores as a normal met (`points`) or not-met (`fail_points`) rule.

```yaml
meta:
  name: VLA SB scoring rubric
  fail_default: 0      # every unmet rule scores 0 unless it sets its own fail_points
```

**Change one rule only** — give it its own `fail_points`, which overrides `fail_default`:

```yaml
  - id: hardware_in_allowlist
    title: "Every hardware resource is a valid catalog name"
    tier: mechanical
    points: 1
    fail_points: -1     # this rule alone costs a point when violated
    source: "Notes comment 5,7; RADAR sec2 (the Ku48f2 vs Ku48f2A bug)"
```

**Restore the old +1/−1 scheme** — delete `fail_default` from `meta`. With neither `fail_default` nor `fail_points` set, an unmet rule defaults to `-points`.

Other common adjustments, all in `rubric.yaml`:

- **Weight important rules higher** — raise `points` so critical checks dominate.
- **Make a check purely informational** — set `points: 0` and `fail_points: 0`; it still appears in the report but never moves the score.
- **Disable a check** — delete its entry entirely.

Both `score_sb.py` and `llm_judge.py` read these values, so scoring stays consistent across all modes.

Two related knobs live in the code rather than the rubric:

- **Pass/fail thresholds** (separation degrees, cycle-time minutes, beam sizes, standard flux calibrators, the ±10% on-source tolerance) are in the `REFERENCE DATA` block at the top of [`src/score_sb.py`](src/score_sb.py) — edit them there.
- **The check logic itself** (what a rule actually tests) lives in the `CHECKS` registry in `src/score_sb.py`; add a new function there and a matching entry in `rubric.yaml` to introduce a new rule.

## Editing the rules / reference data

All ground-truth reference data (hardware allowlist, config schedule, cycle-time table, separation thresholds, beam sizes, standard flux calibrators) lives at the top of [`src/score_sb.py`](src/score_sb.py) under **`REFERENCE DATA`** and is meant to be edited there. The check registry (titles, points, provenance) is in [`rubric.yaml`](rubric.yaml). Authoritative target positions go in [`targets.csv`](targets.csv).
