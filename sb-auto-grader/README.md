# VLA Scheduling-Block Grader

An automated grader for **VLA Scheduling Blocks (SBs)** in the OPT text-import format (`VERSION 7`). It checks an SB — typically one generated by an LLM from a natural-language request — against NRAO/VLA rules, and can also verify it against a known-good ("ground-truth") SB. The goal is to catch mistakes (wrong hardware name, wrong scan order, too little on-source time, a mis-pointed target, …) before any telescope time is used.

Scoring convention: **+1 per rule satisfied, −1 per rule violated** (per-rule point values are configurable — see [Changing the scoring](#changing-the-scoring)).

## What it checks

Every check reports where its verdict came from:

| Source tag | Meaning |
|------------|---------|
| `AUTO`     | deterministic code check (format/validity) |
| `CALC`     | computed vs NRAO guidance (cycle time) |
| `CATALOG`  | resolved from `targets.csv` (target pointing) |
| `GROUND`   | verified against the ground-truth SB |
| `LLM`      | model estimate (fallback only) |
| `MANUAL`   | left unresolved — needs a human |

The four "expert-judgment" checks (phase-cal validity/separation, pointing, depth) resolve in priority order: **ground truth → catalog → LLM → manual flag.** So when a ground-truth SB is available, most of them become automatic and deterministic, and the LLM is only a fallback. See [`docs/HANDOFF.md`](docs/HANDOFF.md) for the full rule list and design notes.

## Requirements

- **Python 3.8+** — the offline modes use only the standard library (no `pip install`).
- **`openai`** — only for the LLM fallback (`pip install -r requirements.txt`), plus access to the lab's Argo gateway. Everything else runs without it.

## Quick start

Grade the example SBs, verifying the expert checks against their ground truth, with **no LLM** (fully deterministic, no Argo, no API key):

```bash
python src/llm_judge.py examples/*_AItest.txt --ground-auto --no-llm
```

Full run, using the Argo LLM only where ground truth can't decide:

```bash
python src/llm_judge.py examples/*_AItest.txt --ground-auto --model "Claude Opus 4.8"
```

A sample of this full run is saved in [`report.txt`](report.txt), produced with:

```bash
python src/llm_judge.py examples/*_AItest.txt --ground-auto --model "Claude Opus 4.8" > report.txt
```

Just the rule-based grader (no ground truth, no LLM):

```bash
python src/score_sb.py examples/*_AItest.txt
```

Compare an AI SB against its ground truth (structural diff, no scoring):

```bash
python src/compare_sb.py --auto --dir examples
```

### Useful options (`llm_judge.py`)

- `--ground-auto` — auto-pair each file with its `*_ground.optSB` and use it as the oracle.
- `--ground <file>` — set the ground-truth SB explicitly (single-file mode).
- `--no-llm` — skip the LLM entirely; unresolved external checks show as `MANUAL`.
- `--targets <csv>` — target-position catalog (default: `targets.csv`).
- `--model <name>` — Argo model, e.g. `GPT-5.5` or `Claude Opus 4.8`.
- `--user <ANL-username>` — Argo API key is your ANL username (or set `ARGO_USER`).

## Changing the scoring

Every rule lives in [`rubric.yaml`](rubric.yaml), one entry per check, and the score it contributes is set by two optional fields — no Python changes needed.

- `points` — awarded when the rule **is met** (PASS). Default `1`.
- `fail_points` — awarded when the rule **is not met** (FAIL). Default is `-points`, i.e. a rule worth `1` costs `-1` when violated (the classic +1/−1 behaviour).

Anything left unresolved (flagged / review / waived) always awards `0`.

**Score 0 instead of −1 when a rule is not met** — set `fail_points: 0` on that rule:

```yaml
  - id: hardware_in_allowlist
    title: "Every hardware resource is a valid catalog name"
    tier: mechanical
    points: 1
    fail_points: 0     # not met -> 0 instead of -1
    source: "Notes comment 5,7; RADAR sec2 (the Ku48f2 vs Ku48f2A bug)"
```

**Apply "not met = 0" (or any value) to every rule at once** — set `fail_default` in the rubric's `meta` block instead of editing each rule. A rule's own `fail_points` still overrides it.

```yaml
meta:
  name: VLA SB scoring rubric
  fail_default: 0      # every unmet rule scores 0 unless it sets its own fail_points
```

Other common adjustments, all in `rubric.yaml`:

- **Weight important rules higher** — raise `points` (and, if you like, make `fail_points` more negative) so critical checks dominate.
- **Make a check purely informational** — set `points: 0` and `fail_points: 0`; it still appears in the report but never moves the score.
- **Disable a check** — delete its entry entirely.

Both `score_sb.py` and `llm_judge.py` read these values, so scoring stays consistent across all modes.

Two related knobs live in the code rather than the rubric:

- **Pass/fail thresholds** (separation degrees, cycle-time minutes, beam sizes, standard flux calibrators, the ±10% on-source tolerance) are in the `REFERENCE DATA` block at the top of [`src/score_sb.py`](src/score_sb.py) — edit them there.
- **The check logic itself** (what a rule actually tests) lives in the `CHECKS` registry in `src/score_sb.py`; add a new function there and a matching entry in `rubric.yaml` to introduce a new rule.

## Editing the rules / reference data

All ground-truth reference data (hardware allowlist, config schedule, cycle-time table, separation thresholds, beam sizes, standard flux calibrators) lives at the top of [`src/score_sb.py`](src/score_sb.py) under **`REFERENCE DATA`** and is meant to be edited there. The check registry (titles, points, provenance) is in [`rubric.yaml`](rubric.yaml). Authoritative target positions go in [`targets.csv`](targets.csv).
